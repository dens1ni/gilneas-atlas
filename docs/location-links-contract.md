# Связанные метки-локации — контракт

## Представление и данные

- Признак `locations[].isLocation:true` делает существующую метку контейнером «Локация». Это не новый тип объекта: `type`, пиктограмма, ID, координаты, фракция, владелец и источники остаются исходными.
- `linkedLocationIds` — упорядоченные точные ID других записей `locations[]`. Связанные записи остаются на карте и имеют собственное досье. Нельзя копировать их описания, объекты или эффекты внутрь родительской записи.
- Географическая/сценарная связь не назначает владельца, не меняет фракцию и не суммирует эффекты. Связь Военного квартала с Каменной тюрьмой не передаёт тюрьму фракции квартала. Собственные объекты тюрьмы и их бонусы/штрафы принадлежат её данным.
- У одной метки может быть несколько локаций-родителей. Круговые, повторные, самоссылки и отсутствующие ID запрещены до сохранения. ID сохраняются буквально: без trim, coercion и переименования.
- Отсутствующие поля старых снимков остаются отсутствующими; загрузка, выбор и переходы по ссылкам не пишут localStorage. Пользовательские `false`, `[]` и авторские связи при обновлении сохраняются.
- Удаление метки убирает только ссылки на неё. Удаление контейнера не удаляет связанные самостоятельные метки, их объекты, эффекты или географию.

## Интерфейс

- Особая декоративная рамка охватывает только типовую иконку; прежние SVG-пути, центр метки, capital-украшения, размер точки и фракционные hover/selected-состояния не меняются.
- У локации есть отдельный раздел «Объекты локации» — ссылки на метки карты и действие «Связать метку». У дочерней точки есть ссылки возврата к родительским локациям.
- Переход вызывает существующий canonical selection, раскрывает досье и центрирует реальную точку. Названия/тип/принадлежность вычисляются по текущему снимку, а не сохраняются копиями в родителе. Дочерняя фракция не должна препятствовать переходу.
- У контейнера без старых inline-объектов его состав показывается ссылками. Если автор уже создал inline-объекты, они не удаляются и доступны отдельно как «Собственные объекты». У обычных меток сохраняется «Объекты владения».
- В редакторе точки есть отметка «Локация», поиск, список доступных реальных меток, добавление и удаление связей. Переключение признака не стирает связи молча. Unsaved операции не меняют снимок до общего атомарного сохранения.
- Минимум 44px для действий, нативная мышь/клавиатура и мобильные раскладки. «Державы и дома» остаётся справа сверху напротив Реестра; досье ниже строки кнопок.

## Обязательные авторские связи

- `military-district` → `stoneward-prison`.
- `emberstone-village` → `emberstone-mine`.
- `duskhaven` → `hammond-farmstead`, `allen-farmstead`, `hayward-fishery`; окружающие сады/конюшни проверяются по имеющемуся описанию.
- `blackwald` → `taldoren`.
- `stormglen` → `bradshaw-mill`.

Все 39 существующих меток проверяются поимённо в `docs/location-links-review.json`. Дополнительные связи основываются на исходных описаниях, не на одном расстоянии. Пользовательские связи — авторская навигация, не новое утверждение о довоенной собственности.

## Приёмка

Проверяются валидация до storage, отсутствие потери старых данных, миграция удалённых и изменённых записей, нативные рамки/переход/возврат, редактирование и отмена, сохранение/перезагрузка, реальные JSON и ZIP, запуск чистого архива на `/` и `/gilneas-atlas/`, полный существующий набор тестов и независимое ревью. Публикация только после зелёной приёмки; исходный Naitroud не изменяется.
